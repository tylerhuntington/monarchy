# Opinionated Defaults and Court Parity

Status: approved direction; implementation and native qualification pending
Pacific date: 2026-11-20

## Scope
Bring the reusable court to the source court's behavior before considering migration. Existing projects retain their own installation. A later owner decision follows side-by-side qualification. Private owner and project facts remain in a separately confirmed private repository.

## Configuration contract
Four plain layers: defaults, project, owner, overrides. Each dotted key declares its allowed homes. Replace uses a single home, min chooses the tightest limit, and union permits only safety additions. Project facts are project-scoped, not court policy. Use strict JSON with an optional _why map and hard numeric bounds, implemented with the Python 3.9 standard library.

Defaults choose how; grants choose whether. Only answered owner boxes activate profiles, backlog work, internal PR approval or delegation. Founding confirms model profiles and timezone once each; successors reuse those records. Never silently substitute models or meter a fallback. Recommended defaults use Claude opus-5-5-1m, xhigh, Fast Mode off for leadership, and Codex gpt-6-astra, ultra, Fast Mode on for workers. Model availability must be checked before dispatch.

The invariant floor includes production approval or rollout, Terraform apply, IAM, secrets, spending, contacting or naming people, and legal authority. The trusted owner route, one writer, restrictive/widening verb classification, 00- names, message headers and unknown-prompt holds are not configurable.

Pins preserve exact approved owner/project bytes, full source commit, SHA-256, owner approval provenance, Monarchy commit and effective-config digest. Sources are read by object ID. Defaults drift holds the court until approved re-pinning. Overrides bind to the court and survive rotation. Standing orders carry stable rule IDs and hash-pinned output; project strings render only as capped, labeled data.

Tracking: [epic #22](https://github.com/tylerhuntington/monarchy/issues/22).

## Verification and completion
Every PR runs the full unittest suite and whitespace check. Runtime behavior begins with failing tests. Refresh skill hashes for changed skill content. The configuration suite covers homes, merge rules, bounds, strict JSON, grant rejection, widening policy changes, drift and value-safe errors. Parity tests reproduce all key rows and resolve all rule/invariant markers. Public hygiene inspects authored files and unpublished ancestors while preserving required third-party attribution.

Native scratch-court proof is separate from fixtures: prompt hold/release, idle pull, all three sign-off dispositions, profile-verified rotation and salvage-backed archive. Retain private source identifiers outside public evidence. Completion requires zero pending parity rows, zero unmapped private preferences and a ready side-by-side qualification plan. No migration follows automatically.

## Explicit cuts
No source-project delegate helper port, separate JSON Schema, config explain verb, nested configuration or deep merge. Overrides are allowlisted. No silent hook installation, live court activation or transfer of another project's grants.
